# Changelog

## 1.0.12 — 2026-11-06

- Nested lists now render at the right depth. A sub-item written CommonMark-style (two spaces under "- ", three under "1. ") nests under its parent, where the third level and deeper used to flatten by one step. Documents already indented with four spaces render as before

## 1.0.11 — 2026-10-22

- A newer version now appears as a card in a news dialog instead of a banner strip: the card lists the release notes newer than the running version, links to the download page, and Don't show again hides it until a still newer version is out
- Occasional announcements from yaiol appear in the same dialog; Settings > General has a new Show news from yaiol switch that turns announcements off completely (the new-version card is not governed by it)
- Number fields show the corrected value at once: a value typed outside the allowed range snaps to the nearest allowed number immediately, even when the stored value did not change
- The editor toolbar buttons, including Insert table, have a lighter look without an outline until hovered

## 1.0.10 — 2026-09-27

- **Settings opens as a full page instead of a dialog.** The settings button in the header now takes over the window below the header: the Display and About sections are listed in a rail on the left and the chosen one fills the rest. The open documents stay loaded underneath, so their undo history and scroll position are still there when you come back. You can leave with the back arrow beside the title, the settings button again, or `Esc`. While the page is open, the other header buttons and the app's keyboard shortcuts are switched off, so none of them can act on a document you can't see
- **Notices shown while a dialog is open can be read.** A notice such as "Copied" used to appear behind the dialog's blurred background, so it came out dim and smeared. It now shows in front of the dialog
- **The formatting toolbar is hidden when no document is open.** It used to show a row of greyed-out buttons over an empty window
- Text fields and dropdowns in the toolbars and dialogs use a lighter grey background, so they stand out from the surface around them
- The README has a new layout, with a logo, a hero screenshot, release and download badges, and a navigation row

## 1.0.9 — 2026-08-26

- **MediaWiki documents keep their formulas and code blocks.** The parser behind MediaWiki discards whatever it doesn't understand, silently and without an error, so `<math>`, `<syntaxhighlight>` and `<pre>` vanished from the preview — taking every formula and every code block in the document with them. Each is now lifted out before parsing and rendered: `<math>` through the same maths engine the other languages use, inline by default and displayed for `display="block"` (which is how Wikipedia writes most of its formulas), and `<syntaxhighlight lang="…">` as a code block in its language
- **Windows can open every markup file {{app:name}} reads.** `.wiki`, `.mediawiki` and `.wikitext` for MediaWiki and `.bb` for BBCode were missing from the installer's file associations, so double-clicking one of those in Explorer never offered Markzen. All fifteen extensions across the eight languages are now registered
- **`Ctrl+K` on a selected address treats it as the link's target rather than its label.** Paste a URL, select it and press `Ctrl+K`: the address goes into the address field and the cursor lands in the empty text field, instead of producing a link whose visible text is the whole URL. Absolute file paths, Windows and POSIX, count as addresses too
- **The convert menu is grouped by what each format is for** — ebooks, word processor, presentation, typesetting, XML, notebook, outline, markup — instead of one flat list. MediaWiki now appears once, among the markup languages: it was listed in both halves of the menu and both entries produced the same file
- **The README states what each markup language can and cannot express** — per language, its file extensions, which live figures work, whether a table of contents is possible, how a formula inside a sentence is written, and what the language simply has no notation for; plus a table of every rendering extension. Both are generated by `npm run check:compat`, so they cannot drift from the code
- Custom `.svg` icons are compiled from the file at build time (`vite-plugin-svgr`), so an icon stays an editable file instead of paths pasted into a component

## 1.0.8 — 2026-08-23

- **Mermaid diagrams that failed with "Syntax error in text" now render.** Each block was handed to `mermaid.run()`, which takes its input from the element's `innerHTML` and rewrites it — decoding entities, dedenting, normalising `<br>` — before parsing, so the diagram source made a round trip through the DOM before Mermaid ever saw it. Diagrams that are valid (unchanged in Mermaid Live) came back as errors: 18 of the 20 blocks in one test document. The fenced block's exact text is now kept on the element and passed straight to `mermaid.render()`, so markup-looking content — a `<br/>` in a mindmap, an `&nbsp;` in a block diagram — reaches Mermaid instead of being eaten by the DOM
- **The diagram size and alignment panel no longer edits the wrong block.** It located a block by counting occurrences of the language in the source, while the preview numbered only the blocks it actually turned into diagrams. A document that *displays* a fenced example of the same language makes the two counts diverge, and every style then landed on the block before the one being pointed at. The panel now finds the block by its own text
- **File pickers reopen in the folder you last used.** Electron 43 made a dialog with no explicit path start in Downloads and stopped the system restoring the previous folder, so every Open began in the wrong place. Markzen now records the folder per dialog — one for documents, one for images — and reopens there, across restarts
- **The update banner's links work, and follow the interface language.** "What's new" pointed at `changelog.html`, a page the website no longer publishes since release notes moved to a single `help/releases/` page — the link was dead. Both banner links also clamped the language to one of four, so a reader in any other language landed on the English page even where a translated one exists
- Bring dependencies up to date, Electron 42 → 43 and `@dbml/core` 8 → 10 among them; DBML moved the auto-increment marker to a field of its own, so primary-key highlighting in DBML diagrams follows it. Vite's config is renamed `vite.config.mjs`

## 1.0.7 — 2026-08-17

- **Markzen now starts in a fraction of the time.** Nearly forty rendering libraries were imported at launch — 35.5 MB in the entry chunk, about 3055 ms of a 3.5 s cold start — paid by everyone who opened a plain `.md`. Each is now loaded the first time a document actually uses it, which takes the entry chunk to 1.48 MB with no preloading; the three libraries only exporting needs (markmap, VexFlow, Plotly) load on the first export, and the interface translations are split per language so one is parsed instead of fifty
- **Box-drawing characters in code blocks are no longer broken.** The cause is Google's webfont subsetter, not the fonts: JetBrains Mono's Google build ships none of the eleven box glyphs while the official build has all of them. JetBrains Mono and Source Code Pro are therefore bundled with Markzen in three weights each, which also makes them work offline on a fresh profile. Cascadia Code and Fira Code are replaced by Cascadia Mono and Fira Mono — the ligature-free variants, because a ligature draws `!=` as a single `≠` and a document viewer must show the characters that are in the file. DM Mono is dropped; its upstream font has the block in no build
- **A code font now travels with the exported file.** Bundled fonts are embedded as data URIs in HTML and PDF exports, so a document keeps its alignment on a machine that never had the font. The editor pane also takes the same font stack as the preview instead of its own hardcoded fallback chain, so the two panes and the export finally agree
- **One Appearance button replaces four toolbar controls.** The style template and the heading, body and code font pickers now sit in a single labelled panel behind a palette button
- **Any packaged release can be timed without a special build.** Five startup marks from OS process creation to the renderer's first paint, writing nothing unless `YAIOL_STARTUP_LOG` is set
- Adopt the shared catalog's `.pop-form` / `.pop-field` popover-panel classes, and take the shared `i18n-split` build step in as `main/scripts/i18n-split.mjs` so the build reaches nothing outside the repo

## 1.0.6 — 2026-08-07

- Open, edit, preview and export **BBCode** (`.bbcode`) — the eighth markup format, with its own file icon and file association. Pandoc can write BBCode but cannot read it, so exporting uses its `bbcode_hubzilla` dialect (the only one that keeps real headings, tables, rules and images) while reading uses Markzen's own parser, deliberately tolerant of the many forum dialects
- Insert a table from the editor toolbar: pick the size on a hover grid and Markzen writes it in whatever markup is open — Markdown, AsciiDoc, reStructuredText, Org, Textile, Djot, MediaWiki or BBCode
- Fix the submenus of the Convert menu (Ebooks, Word Processor, Presentation, …) being impossible to open: the flyout was drawn inside the menu's own scroll box, which clipped it out of sight as soon as the menu was long enough to scroll
- Fix menus being capped at a fixed 320 px and scrolling even with plenty of window left — a dropdown now uses the height actually available on screen
- Fix several submenus staying on screen at once when moving down a menu, each lingering until its own timer expired
- Add a shared hover-grid table-size picker to the UI catalog, and run the toolbar's table insert and the tab-separated-paste table through one shared insertion path

## 1.0.5 — 2026-08-03

- Fix CLI exports leaving an orphan temp folder behind on every run: each run now sweeps the leftover folders of runs that have exited, instead of trying to delete its own cache on the way out (which can never work on Windows while Chromium still holds it open)

- Add a shared radio control to the UI catalog and move the link/image popup onto the shared input/button styling
